# EyeCare v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sideloaded Android app that sends 20-20-20 eye breaks, hourly long breaks and season-tuned water reminders inside wake hours, and keeps working with the screen off, the app closed and after a reboot.

**Architecture:** A Capacitor 8 shell with a React 19 UI. All timing lives in a pure-Java `Scheduler`: static transitions that change a `DayState`, unit-tested with JUnit. A thin Android layer (`Engine`, `Notifier`, `EventReceiver`) stores state in SharedPreferences, sets one exact alarm per event kind and posts notifications. A local Capacitor plugin (`EyeCarePlugin`) connects React to `Engine`. React only displays state and calls the plugin.

**Tech Stack:** Capacitor ^8.3.4, React ^19.2.6, Vite ^8.0.12, TypeScript ~6.0.2, Java (JDK 25, Gradle 9.1, AGP from the Capacitor template), JUnit 4.13.2, Python 3 + Pillow (dev-only, to draw the animations).

**Spec:** [docs/superpowers/specs/2026-10-31-eyecare-v1-design.md](../specs/2026-10-31-eyecare-v1-design.md)

## Global Constraints

- Project root is `D:\DigitalCare`: the Vite app sits at the root, Capacitor's `android/` sits beside it, and `docs/` stays as it is.
- Versions match `D:\BhumiSetu\client`: `@capacitor/core|android|cli ^8.3.4`, `react`/`react-dom ^19.2.6`, `vite ^8.0.12`, `@vitejs/plugin-react ^6.0.1`, `typescript ~6.0.2`, `@types/react ^19.2.14`, `@types/react-dom ^19.2.3`. No other npm dependencies: no router, no state library, no Tailwind. Use plain CSS.
- App id `com.eyecare.app`, app name `EyeCare`, Java package `com.eyecare.app`, minSdk 26, target/compile 36.
- `Settings`, `DayState`, `Season` and `Scheduler` import only `java.*` (they use `java.time`). There are no `android.*` and no `org.json` imports in these files.
- Times are epoch-ms `long`s. In Java, `0` means "none". The bridge sends `null` for none.
- `Engine` is the only code that reads or writes SharedPreferences (file `"eyecare"`, keys `"settings"` and `"day"`, JSON strings). React stores nothing except the dismissed Vivo steps flag in `localStorage`.
- Every public `Engine` method is `static synchronized`, because the plugin thread and the receiver's main thread both call it.
- Notification channel ids are fixed and never deleted: `short_break`, `long_break`, `break_over`, `water`.
- Alarms use `AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP, t, pi)`. Each `Kind` has one PendingIntent with action `com.eyecare.app.ALARM.<KIND>` and request code `kind.ordinal()`, so setting it again replaces the old alarm.
- The manifest carries this comment, verbatim: `shortcut: USE_EXACT_ALARM is fine for sideload, Play Store publishing needs policy review`.
- Snooze is fixed at 5 min. The first water reminder comes at wake + 10 min. Water spacing is clamped to 30–120 min.
- UI: touch targets ≥ 48 px, AA text contrast, countdowns always shown as text, font sizes in `rem`.
- **Deliberate deviations from the spec**, listed so a reviewer doesn't flag them:
  - (a) `State` gains `tip: string`, so the season tips live only in Java.
  - (b) `SCHEDULE_EXACT_ALARM` is added with `maxSdkVersion="32"`, because `USE_EXACT_ALARM` doesn't exist on Android 12–12L.
  - (c) The `DAY_START`, `BREAK_END` and fire handlers use the fire time `now` as the base instead of the planned time, so a late alarm never produces a past time. Tests fire on time, so the spec's values hold.
  - (d) "Stale schedule" safety net: when the app comes to the front and any armed alarm is more than 60 s overdue, or nothing is armed (first launch), the engine recomputes from now.
  - (e) The break notification is cancelled whenever no break is running (skip, snooze, pause, recompute).
  - (f) `POST_NOTIFICATIONS` is requested once at startup by `MainActivity`. The setup card's Notifications button opens the app's notification settings, which also works after "don't ask again".
  - (g) The UI uses one dark palette, with no light theme.

## Review Focus

1. **A late alarm after sleep time** (Doze or Vivo delays): no break or water reminder is shown, and only `DAY_START` stays armed. Owned by Task 3 (`lateAlarmAfterSleepShowsNothing`, `lateWaterAfterSleepShowsNothing`).
2. **Changing wake or sleep times mid-day** keeps today's glass count. The day is matched by its date, not its start time. Owned by Task 4 (`settingsChangeMidDayKeepsGlasses`).
3. **Phone off at wake time** (missed `DAY_START`): the first recompute after boot starts a fresh day with 0 glasses. Owned by Task 4 (`missedDayStartResetsOnRecompute`).
4. **Garbage from the settings form** (an empty number field sends `null`, plus `0`, out-of-range values and bad times) falls back to defaults or the §6 ranges, and never causes a 0-min alarm loop. Owned by Task 2 (`clampKeepsRangesAndDefaults`) and Task 5 (`JsonTest` null handling).
5. **Saving settings while paused** keeps the pause and doesn't re-arm breaks or water. Owned by Task 4 (`settingsSaveWhilePausedStaysPaused`).

### Task 3: Day start, eye breaks and water transitions

**Files:**
- Modify: `android/app/src/main/java/com/eyecare/app/Scheduler.java`
- Test: `android/app/src/test/java/com/eyecare/app/BreakTest.java`, `WaterTest.java`

**Interfaces:**
- Consumes: Task 2's `Settings`, `DayState`, `Window`, `windowAt`, `nextWake`, `goal`.
- Produces. All are `static` and take `(Settings s, DayState d, long now, ZoneId z)`; the transitions mutate `d`:
  - `void onDayStart(...)`
  - `boolean onBreak(...)`: returns true when the break should be shown.
  - `void onBreakEnd(...)`, `void skip(...)`, `void snooze(...)`
  - `boolean onWater(...)`: returns true when the reminder should be shown.
  - `void logGlass(...)`
  - `long waterNext(...)`: returns the next water time from `now`, or 0.
  - `static boolean nextBreakLong(Settings s, DayState d)`: `snoozed ? breakLong : (breakCount + 1) % longEveryN == 0`.
  - `static final long SNOOZE_MS = 5 * MIN`

Rules. `w = windowAt(now)`. `breakAt(t)` = `t` when `breaksOn && w != null && t < w.end`, else 0. `cutoff = w.end − stopBeforeSleepMin·MIN`. Every transition ends with `d.nextDayStartAt = nextWake(now)`.

| Transition | Effect on `d` |
|---|---|
| `onDayStart` | glasses=0, breakCount=0, dayDate=w.date, pausedUntil=0, breakEndAt=0, snoozed=false, nextBreakAt=breakAt(now+shortEveryMin), waterFirst=true, nextWaterAt = now+10 min if waterOn and ≤ cutoff, else 0 |
| `onBreak` | if `w == null` or `!breaksOn`: nextBreakAt=0, snoozed=false, return false. Else: if `!snoozed`, breakCount++ and breakLong = breakCount % longEveryN == 0. Then snoozed=false, nextBreakAt=0, breakEndAt = now + (breakLong ? longMin·MIN : shortSec·1000), return true |
| `onBreakEnd` | breakEndAt=0, nextBreakAt=breakAt(now+shortEveryMin) |
| `skip` | breakEndAt=0, snoozed=false, nextBreakAt=breakAt(now+shortEveryMin) |
| `snooze` | breakEndAt=0, nextBreakAt=breakAt(now+SNOOZE_MS), snoozed = nextBreakAt != 0 |
| `onWater` | if `w == null` or `!waterOn`: nextWaterAt=0, return false. Else: waterFirst=false, nextWaterAt=waterNext(now), return true |
| `logGlass` | glasses++, waterFirst=false, nextWaterAt = pausedUntil > now ? 0 : waterNext(now) |
| `waterNext` | 0 if `!waterOn`, `w == null`, `now ≥ cutoff` or `left = goal − glasses ≤ 0`. Otherwise interval = smartWater ? clamp((cutoff−now)/left, 30 MIN, 120 MIN) : customEveryMin·MIN, and the result is now+interval, or 0 if that is > cutoff |

### Task 4: Pause, recompute-from-now, alarm set and stale check

**Files:**
- Modify: `android/app/src/main/java/com/eyecare/app/Scheduler.java`
- Test: `android/app/src/test/java/com/eyecare/app/PauseRecomputeTest.java`

**Interfaces:**
- Consumes: everything from Task 3.
- Produces:
  - `enum Kind { BREAK, BREAK_END, WATER, DAY_START, RESUME }`, nested as `Scheduler.Kind`.
  - `static void recompute(Settings s, DayState d, long now, ZoneId z)`
  - `static void pause(Settings s, DayState d, long now, ZoneId z, Integer minutes)`: `null` means until tomorrow.
  - `static void resume(Settings s, DayState d, long now, ZoneId z)`
  - `static long alarmAt(Kind k, DayState d)`: 0 means cancel.
  - `static boolean stale(DayState d, long now)`

Rules:
- `recompute`:
  1. If `w != null` and `w.date.toEpochDay() != d.dayDate`, start a new day: glasses=0, breakCount=0, dayDate=w.date, waterFirst=false.
  2. Set breakEndAt=0 and snoozed=false.
  3. If `pausedUntil > now`, set nextBreakAt and nextWaterAt to 0. Otherwise set pausedUntil=0, nextBreakAt=breakAt(now+shortEveryMin) and nextWaterAt=waterNext(now).
  4. Finish by setting nextDayStartAt.
- `onDayStart` (change it from Task 3): if `windowAt(now) == null`, the alarm is stale, for example after a settings change; call `recompute` and return.
- `pause`: pausedUntil = minutes == null ? nextWake(now) : now + minutes·MIN. Set nextBreakAt, breakEndAt and nextWaterAt to 0, and snoozed=false. Finish.
- `resume`: set pausedUntil=0, then `recompute`.
- `alarmAt`:
  - BREAK = nextBreakAt, BREAK_END = breakEndAt, WATER = nextWaterAt.
